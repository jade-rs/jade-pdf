# 長方形からの罫線抽出

ページ本文の`re`で構築し、strokeを伴う`S`、`s`、`B`、`B*`、`b`、`b*`で描く長方形から、元の四辺を保存する。
`f`だけの塗りや`n`の取消から枠を作らない。既存の直線・細い塗りの抽出は別の経路で維持する。
APIの形・依存・CLIは追加しない。

構築時のCTMで四隅をページ座標へ写し、非有限値・退化・任意回転や斜交の外接矩形を罫線にしない。
軸平行の拡大、反転、90度回転は扱う。描画時のCTMと線幅から、水平辺・垂直辺それぞれの法線幅を測る。
`q/Q`は描画状態を復元するが、構築済みpathを消さない。Contents配列は字句を変えずに連結し、pathと状態を引き継ぐ。

保存対象は、Device色で黒を確認でき、stroke alphaが1、通常合成でmaskがなく、実線の辺である。
fill側のalphaをstrokeへ流用しない。`CS`による既知Device色の初期黒への変更も反映する。
Deviceの既定色空間置換がある場合は、未知の色変換をWordの黒と決めつけない。
ExtGStateは所属ページのResourcesから解決し、互換入力の親Resourcesも照合する。
未知のgs、未対応の効果、壊れた辞書・重複キー、dashや色の不確実性をno-opと見なさない。

描画時に有効な凸clipとMediaBox/CropBox内に、線幅を含む辺の外周全体がある場合だけ保存する。
一部が切れた辺をclip境界で閉じ直さない。`W S`では現在pathを描いた後にclipが効く。
未対応clipがあるページ、hairline、未確認の色・透明度・Form内の枠の完全再現は、この追加処理の受入範囲に含めない。
これらを含むPDF全体の忠実度・strict診断は別途改善・検証が必要である。

走査・path・状態stack・連結本文・Resourceの索引は既存の共有資源制限と停止状態に従う。
文字抽出用の未完operand回復を使って、文字列内の偽`re/S`を実行しない。
元の座標は既存の罫線結合処理で整数pointへ正規化される。

## 原本による確認と残る問題

事前に全ページ・権利・プライバシーと96セルのgoldを確認したBIPM SI Prefixesでは、
既存の解析が捨てていた72個の黒枠を、native/pure両経路で288辺として確認できた。
原本との座標差は既存の正規化の範囲で最大0.488pt、線幅は元の0.25ptを保持し、125文字要素・画像2枚は変わらない。
これは発見後の幾何照合であり、新たな未見資料での精度評価ではない。

DOCX側は離れた倍率欄を24個の一セル表へ分け、因子・名前・記号の前に置いてしまう。
四列の所属、色、余白、改ページなどの全体goldは未達である。罫線の抽出数だけで表の再現成功やproduction readyとは判断しない。

規則はAdobe公開の[PDF 32000-1:2008](https://opensource.adobe.com/dc-acrobat-sdk-docs/standards/pdfstandards/pdf/PDF32000_2008.pdf)
のpath・clip・色の定義に従う。ユーザー指定のkanpoの、元の描画と文字の対応を確認してから構造へ移す設計も参考にし、
文字列や資料名による分岐・原本にない辺の補完は行わない。
