# 部分的な外辺を持つ表と数値列の配置

長い縦罫線だけで表の左右を決めると、ヘッダーの一部で途切れる外辺が候補から落ちる。
国税庁の賞与税率表では、全高370ptに対する291ptの外辺が80%の条件を満たさず、
一方のページの表全体と、もう一方のページの左側の列群が表として出力されていなかった。

上下の横罫線の端と対応し、実際に既存の行帯を覆う縦罫線がある場合に、範囲外の外辺を
候補へ戻す。片方の横辺しか確認できない場合や、対応する縦辺がない場合は補わない。
新しく罫線を描き足したり、失われた表の行を推測して増やす処理ではない。

## 数値の右端

原本で右端が揃う数値を左端のindentで配置すると、代替書体が少し幅広いだけで
`82` が `8` と `2` に折り返される。同じセルにある複数の数値行について、
左右のbounds・書体サイズが有効でセル内に収まり、右辺からの距離がem以内で、
右端の差が最大emの10%未満、左端の差が最大emの半分以上ある場合に右揃えと判断する。
字面の右端はglyphのadvanceと異なるため、小さいsidebearingの差を扱う。

元の右端とセル右辺との差を右余白として保持し、元の文字・書体サイズ・色・行間を残す。
同じ幅の数値だけの群、単独行、左揃え・中央揃え、不明な座標やサイズでは適用しない。
対象の数値判定はASCIIの数字・符号・区切りだけで行い、本文の文字を正規化しない。
保持するのは原本boundsに対応する余白であり、代替書体の字形や描画位置の完全一致ではない。

## 罫線と下線

原本gridと照合した水平線は、通常の一行・複数行セルでも文字の下線として使わない。
横辺と縦辺の端点が別々に丸められるため、端点の差は1pt以内で照合する。
高さの許容幅は従来の0.5ptを維持する。セル内の短い独立した本文下線は残す。
一段落のfallbackだけに限定していた境界の除外を、通常配置にも適用している。

## 検証範囲

所有PDFの公開byte APIテストで、左右の部分外辺、可変桁の右揃え、左揃えの保持、
通常セルの罫線・独立下線をRedから確認する。位置・列幅・書体サイズの24ケースのPBTと、
sidebearingの24ケースのPBT、範囲外座標・片側だけの根拠などの負例も含む。
公開API・CLI・依存の変更はなく、追跡PDF fixtureは3件のままである。

native40結果、Chromium/WebKit各56結果を変更前と照合した。既存native入力の変更は
BERTの一段落と印紙税額一覧の16段落の罫線由来の下線の除去に限られ、
本文・他の文字書式・行間・ID・他のpackage部品は一致する。
ブラウザの既存25ケースは出力がバイト単位で一致する。
新しい3件の所有対照PDFは両モードで両ブラウザとnativeのDOCXが一致し、
文字列・サイズ・右揃えの有無を事前の期待値と照合する。
対照PDFの単一行`Ctl`セルの縦中央配置は既存の制約として残る。

35ページの候補を描画し、変更したBERTの1ページ、印紙税額一覧の2ページ、
所有対照3ページ、賞与税率表3ページを個別に目視した。
残りのBERT26ページは変更前と画素が一致する。35ページすべてを個別に目視した判定ではない。

## 賞与税率表の結果と未解決部分

[国税庁の賞与税率表](https://www.nta.go.jp/publication/pamph/gensen/zeigakuhyo2026/data/15-16.pdf)
は、最初の固定変換器で評価する前に全ページ・権利・個人情報の有無を確認し、
[30項目の正解](../corpus/nta-bonus-rate-2026-prospective-gold.json)を保存済みである。
今回の修正時点では既知の回帰資料であり、未見の独立した評価と数え直さない。

両ページの主な列が2つの編集可能な表へ戻り、328の数値段落で右端を保持する。
文字の多重集合を空白以外で照合し、追加・欠落がないことを確認する。
事前の30論理項目・見出しは、対応する列と相対的な行で表示されることを目視確認した。
本文の税率行は独立したWord行ではなく、大きいgrid行内の複数段落であるため、
この確認をすべての論理セルの構造・編集性の合格とはしない。

原本2ページに対してWordでは3ページとなり、最初のfooterが別ページへ出る。
表全体の位置、法令名行の折り返し、和文tracking、元の字形、罫線幅や結合にも課題が残る。
BERTの図をgridとして扱う既存の誤り、27ページへの再flow、印紙税額一覧の画像・曲線などの
quality上の問題も未解決である。Microsoft Wordの描画は未確認で、文書全体もプロダクション品質も未合格とする。

原本・font・生成DOCXはprivate QAにのみ保存する。
限定した結果は[検証記録](../corpus/validation-native-partial-tables.json)、
kanpo-parser / kanpo-docxから参考にした設計の扱いは[参照記録](source_typography_and_table_opening.md#参照)を参照。
