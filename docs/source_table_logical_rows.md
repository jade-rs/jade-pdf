# 結合見出しの下の編集可能な本文行

横結合した見出しと縦罫線だけを持つ表では、複数の項目が一つのWord行へまとめられる場合がある。文字の集合が一致しても、項目と数値が別々に編集できなければ行の対応を復元したとは扱えない。原本の表示行を照合し、同期した本文を個別のWord行へ分ける。

対象は、原本セルとの対応が確認済みの罫線表に限る。二つ以上の非空セルに3行以上の本文があり、各行の上端が一致するときだけ分割する。本文より小さい単位行が先頭に一つある場合は、対応する単位のないセルを空欄にする。行数の不一致、縦結合、入れ子表、照合できないセルは既存の経路を保つ。

横結合、元の外周と縦辺、文字の位置・run書式を保持する。元になかった本文の横罫線を追加しない。分割後の行高の和は元の物理帯の高さと一致させ、文字が各帯へ収まることを確認する。元の複数行から判定した数値の右端揃えと右余白も引き継ぐ。一行だけを見て揃えを再推定すると、桁数の異なる数値が折り返すためである。

容量検査は実際のbuilderと同じ遅延計算を共有し、段落を生成しない。公開WASMの`inspectPdfJson`を先に実行しても、その後のdefault/strict変換が生成する段落IDを変えない。表の代表値を選ぶ診断値は、行の細分によって変わることがある。

## 検証と限界

実装はRed→Greenとプロパティテストで進め、結合見出し・描画順の反転・単位行・左右の数値揃え・同期しない本文を確認した。原本6件の全ページと期待値を変換前に固定している。既に単体APIで使用した既知の対照であり、未見資料の精度率ではない。

source `c1b2162`の765 Rustファイルで、default全体検査は2,540成功・0失敗・42ignore（146群）。最初の全体実行で発生したIPC子プロセスの起動タイムアウトはログを保存した。同じソースの単独検査と新しい全体検査が成功しており、タイムアウトや検査条件は変更していない。

実ファイルはnative 164条件（142成功・22拒否）、Chromium/WebKit各172条件（145成功・27拒否）を確認した。既存472出力のうち462出力は検証済み親とbyte単位で一致し、意図した変更はnative 4出力とbrowser各3出力。追加6件の36出力は原本の行・セル対応に一致した。16件の所有表対照について96出力の検査を直接または同一出力から継承し、browserの64出力はnativeのDOCXと段落IDを含めてbyte単位で一致する。両browserの172出力と86件の診断結果も一致した。

nativeの変更・追加DOCX全13ページは、個別確認済みの直前段階と描画RGBが完全一致することを確認した。browserの変更公開資料は6ページを直接確認した。暦の全体資料の2・4ページは親とRGB一致し、1・3・5ページは変更を確認した。元の太字・色・サイズの12出力と、既存の表書式の描画確認もbyte一致で継承する。親・原本・期待値23,550ファイルを再照合した。

国税庁の賞与表はnativeで元の30基準を満たすが、暗号化された原本をbrowserで扱う制限は残る。暦要項の元の44基準はnative 36成功・8失敗、browser 27成功・17失敗。日付・時刻の区切り不足、月相の図形、既存の`1.156`の折返し・欠け、原本の文字集合・寸法基準は未解決である。行分割で折返し位置が変わる箇所もあり、原本と同じ見た目を保証しない。同期しない複数行セル、代替fontの字形・baseline、既存の背景・段組・改ページの課題も残る。

この記録は限定した機能の検証であり、文書全体の本番品質の合格ではない。[検証台帳](../corpus/validation-source-table-logical-rows.json)に固定したproducerと実行記録を記載する。kanpoから参考にした表と文字の所有対応の考え方は[参照記録](source_typography_and_table_opening.md#参照)を参照。独自ライセンスのコードを転記せず、追加のruntime依存も導入していない。
