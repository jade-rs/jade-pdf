# 2列散文への表の誤生成を防ぐ

左右に並ぶ散文を罫線なし表と誤認すると、原本にないセルと罫線が追加される。実際のgraphic tableがないページに限り、原本文字の全X開始位置、密な散文行とWordの2列frameが揃う場合は、表推定から外して既存の段組み経路へ渡す。実際の罫線表と識別子/説明の表は既存経路を維持する。

条件は散文が各列8行以上、各行3語以上・小文字を含む・幅8em以上であること。散文だけでなく全ての原本文字要素を調べ、X開始位置のclusterがちょうど2つであり、有限で正の文字幅がページ内に収まり、実際のWord2列frameも構成できることを要求する。短い識別子列を無視して3列を2列と誤認しない。裸のページ番号の復元条件は変更しない。

kanpo-parser/kanpo-docxの表・書式保持を調査した継続作業であり、原本の構造と照合して編集可能なWord要素を選ぶ方針を独立実装した。参照元のコード・依存を追加していない。

## 検証

公開byte APIのRedを保存してから実装した。広い条件の試作は3列原本を階段状の上下位置にしてしまったため採用せず、3列散文および短い識別子＋2散文列のRedを追加した。6テスト、2つのproperty各24例を通した。771 Rustファイルを固定した全体検査は2,564成功・0失敗・42ignored、149 groupsである。

CLI188回（166成功・22期待拒否）、Chromium/WebKit計392回（各169成功・27期待拒否）、合計580回を確認した。既存574件の成功・拒否条件は同じ。568成果物はqualified parentとRAW byte一致し、変更は2列散文の6成果物だけである。6成果物すべてで原本100段落のliteral文字列が各1回あり、実際のWord2列sectionが4つあり、原本にない表は0個になった。出力4ページは既知の直接レビュー済み成果物とRAW byte一致する。元の数字footer喪失や代替fontのbaseline差は全体受け入れの対象に含めていない。

追加の3列対照は6成果物すべてqualified parentとRAW byte一致し、31 literal文字列・非空白文字の個数・10行3列表の既存fallbackを維持した。一方、原本にない表が生じるsource no-table goldは6件とも失敗として保持する。既存との互換性を原本再現の成功として数えない。親と広い試作の各1ページを直接確認した記録も保存した。

両browser engineは196成果物・98検査で一致する。限定したnative/browser比較112組は108組RAW一致、4組は生成段落IDだけ異なり、親の7ページRGB照合を同一byte成果物から継承する。段落IDの決定性は主張しない。親・原本・gold計33,093ファイルを再照合した。過去の正解を変更せず、既知資料の追試を未見精度として扱わない。

Censusは97 literal field/description、7,981非空白文字、4ページ、原本130項目の128成功・2失敗を維持した。最初の未見評価4成功・126失敗も変更しない。Censusの見出し下線・配置、NAOJの図形・日付区切り、一般の改ページなどの残課題があり、文書全体のproduction readinessは未達である。
