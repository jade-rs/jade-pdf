# 確認済み基線差のDOCXへの保存

正立した元の文字と通常文字の基線を確認できる場合、小さい文字の相対位置を
OOXMLの `w:position` に半point単位で保存する。文字サイズは元のまま保持し、
`w:vertAlign` による自動縮小は使わない。既存のページ縮小が必要な場合は、
位置指定も同じ比率で縮小する。ファイル出力とbytes/WASM出力は共通の梱包処理を通る。
API・CLI・設定・依存の追加はない。

通常文字に対して0.5〜0.85倍の文字サイズ、0.25pt以上かつ0.6em以下の基線差だけを対象とする。
通常文字の基線が行全体で一致しない場合は、左右直近の通常文字を確認する。
存在する参照文字の基線が未知・非有限・不一致なら、位置を推測しない。

既存の4pt行分割から外れた小文字群は、重ならない2em以内の通常文字を持つ候補行が
一つだけの場合に戻す。探索する垂直範囲と候補行数には上限を設け、
通常の単語空白（0.8em以下）でつながる小文字群は一体で扱い、幅が通常文字の2emを超える群は移動しない。
長い脚注行の一部だけを添字へ変えず、元のspanがglyph単位でも同じ制限を使う。
重なった矩形、複数候補、入れ子の移動も回復しない。
先に確認した段間とその垂直範囲を保持し、各段の通常文字サイズを別々に照合する。
段を横断する矩形は、この行回復の根拠にしない。
移動した行だけ元の独立した空白を再照合し、近接文字の基線と水平間隔が合う空白を保持する。

## 検証範囲

NISTの2022 CODATA wallet PDFでは、事前に記録した26件の数値列が元の行順で連続し、
指数を持つ19件について独立したPDF glyph行列から求めた基線差とOOXML位置が
半pointの丸め範囲内で一致した。数量名・数値・単位の表の対応、式全体やページ全体の合格ではない。

GNU Helloの索引では、別段の大きな見出しに参照番号が移る中間版の回帰を検出した。
段ごとの照合後は、原本の46索引項目と参照番号の対応が一致し、native DOCX全体も
マージ済みの基準版と同一になった。この追加診断は原本から回帰発見後に作ったもので、
未見資料の事前goldとは扱わない。

未知Unicode、未確認の数学記号、数式構造、表の行列関係、段組と改ページ、vector図、
タイトルの単語間隔には未解決の問題がある。LibreOfficeの検査はMicrosoft Wordでの
忠実度を保証しない。資料ごとの詳細と不合格事項は[検証台帳](../corpus/validation-inline-baselines.json)に記録する。
