# セル内の独立した文字群の原本位置

新旧金額など、同じ罫線セルの離れた文字群を一つの連続した文字列へ詰めず、編集可能なWordのタブで原本の位置へ置く。原本の行・文字・fontを照合できる非結合セルの一行だけへ適用する。

## 適用する範囲

既存の罫線表のセル所有を使い、一つの物理行・一列・一表示行に限る。表示行と原本断片の個数・非空白文字が一致し、全座標と文字高が有限かつ正で、文字矩形がセル内に収まる必要がある。別ページ、重なり、制御文字、空白だけの断片、未対応文字、既存の明示glyph配置には適用しない。結合セル、複数行、独立した閉じたboxを扱う別経路は従来の配置を使う。

隣接断片の空隙が両者の最大font sizeの二倍を越えた行だけを対象とする。その行の0.5ptを越える各空隙へ、セル左端からの次の断片の原点をtwipへ一度丸めて保存する。推定した先頭空白だけをタブ文字へ置換し、元の非空白文字とrunの書式を保つ。実際の空白数から原本距離を推測しない。

## 文字幅と次のタブまでの容量

埋め込みface属性だけを根拠にせず、実際のfont bytesからcmapと水平advanceを読む。GSUB、GPOS、kern、可変font、AATの各tableを持つfontはこの小さい測定器では確認しない。未定義glyph、無効font、長すぎる列も旧配置へ戻す。Wordのhalf-point文字高で実測幅を積算し、現在位置が次のstopへ達する、またはセル右端を越える場合は適用しない。

従来の互換Helveticaの単純ASCIIに限り、未埋め込みでも正規のhalf-point文字高・regular・Tr2なしを確認し、宣言された原本幅と一文字一emの大きい方を保守的な幅上限とする。これでも次のstopまで収まらなければ旧配置を使う。未知の代替fontや複雑なshapingへ推測で広げない。

段落は原本の左原点と上端からの行間を使い、セル余白と中央・右揃えを二重に加えない。罫線、列幅、行高、表全高や他のセルは変更しない。公開API・CLI・依存・tracked PDF fixtureの追加はない。

Wordの明示的なタブstopの扱いは[MicrosoftのWordprocessingML資料](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.tabstop?view=openxml-3.0.1)を参照する。現在の表示確認はLibreOfficeであり、Microsoft Word実機での表示は未確認である。
