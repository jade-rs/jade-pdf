# 原本の装飾付きページ番号の保持

本文末のページ番号を通常段落で配置すると、大きい先頭余白が次のページへ押し出される。
国税庁の賞与税率表では原本の2ページがWordの3ページとなり、15の番号だけが
余分なページに出ていた。文字を削除せず、確認できた各原本行をfooter partへ移す。

抽出・配置の対象ページが2ページ以上連続し、各ページに候補が一つだけあり、番号が一つずつ増え、
装飾とWordの文字書式が一致する場合に限定する。候補は回転のないページの下端6%以内で、
中央付近に中央揃えされた行とする。両端が同じem dashまたはhorizontal barで、
間がASCII数字である場合だけを扱い、非有限座標・不正な書体サイズ・整数overflowは拒否する。
既存の反復footerが一つでも採用されている場合は上書きしない。

照合用の空白除外や数字の桁のまとめ方を出力文字へ適用しない。原本の空白・線・番号・runと
書式をそのまま保持し、sectionから各ページのfooter partへ参照を付ける。
裸のページ番号を除く既存の判定を拡張する変更ではない。公開API・CLI・依存の変更はない。

## 検証

公開byte APIの回帰を変更前で失敗させ、実装後に成功させた。
原本の開始番号・桁数・書体サイズ・位置を変える24ケースのPBTでは、
本文・footerの文字とサイズ、section参照を辿った原本ページ順まで確認する。
単一ページ、非連番、本文位置、紛らわしい装飾、範囲外の値も扱う。
defaultは2429 passed / 0 failed / 32 ignored、fmtとClippyは成功している。

nativeは56結果、Chromium/WebKitは各72結果を受け入れ対象として照合した。
それぞれ52成功・4期待済み拒否、59成功・13期待済み拒否である。
既存nativeのDOCX変更は賞与税率表の通常変換だけで、ブラウザ既存28ケースのDOCXは
変更前とバイト単位で一致する。原本のstrict拒否はそのまま保持する。

所有する8対照では、番号の保持・9から10への桁数変化・太字と青色・候補の一意性・
既存footerとの競合・本文位置などを確認する。両ブラウザは同じ結果とハッシュになる。
続けて呼ぶstrict変換の陽性2対照は、nativeと比べて生成段落IDだけが異なる。
section遷移の段落IDは一致し、内容段落とfooterのIDはページ数から予想される一定量だけずれる。
ID以外のXML・文字・書式・位置指定・関係・部品を厳密に照合している。
この確認を両モードすべてのnative/browserバイト一致とは表現しない。

最初の曖昧候補の所有対照は、二つ目の行のglyph上端が下端6%の範囲外であり、
「候補が二つ」の負例になっていなかった。元の正解・入力・全結果を保存し、
native2結果・browser4結果を受け入れ対象から除外した。
二つの行が範囲内になる別の入力と正解を初回実行前に作り、変更前とのバイト一致を確認した。
生の実行数はnative58・browser148であり、除外分を成功として数えていない。

最初のRed入力も、ToUnicodeなしのWinAnsi octalが置換文字になっていて問題を分離できなかった。
明示ToUnicodeと変換前のliteral Unicode検査で入力を直し、変更前で失敗することを確認し直した。
これをWinAnsi経路の修正の証拠とはしない。
また、追加のworkspace実行で差分crateのUnicode2テストが失敗したが、
変更前でも変換用SDK7961で同じ失敗を再現し、差分用の固定SDK8111では両方成功した。
CIと同じdefault検証は変換対象のcrateを検査する。

## 原本での結果と制約

賞与税率表は2つの表と328数値段落を保ち、原本2ページに対してWordも2ページとなる。
すべての文字と空白の多重集合、footerの全run書式を変更前と照合する。
footer移動・source毎のsection遷移・生成段落IDを除く本文要素と表は一致し、
他のpackage部品の変更はfooterの宣言と参照の追加に限られる。
事前登録した30項目は、現在の両ページの対応する列と相対行で再度目視確認した。
所有対照5ページを含む変更後7ページを個別に目視した。

ページ番号が載るページは正しくなるが、描画位置や字形の完全一致ではない。
独立したPDF抽出では、数字の水平中心が原本から約15ptと11pt右、上端が約7pt上にある。
原本の和文trackingと字形、法令名の折り返し、罫線の幅や結合、論理的な税率行の構造は
未解決である。Microsoft Wordでの描画も未確認で、文書全体の品質合格とはしない。

原本・font・生成DOCXはprivate QAにのみ保存し、追跡PDF fixtureは3件を維持する。
既知資料の改善を未見の精度として数え直さない。
