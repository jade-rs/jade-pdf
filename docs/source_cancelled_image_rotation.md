# ページと画像の回転の相殺

ページ回転で画像のCTMの回転が相殺される場合に、画像をもう一度回さない。表示用の矩形・幅と高さ・回転角を同じ座標系へ揃え、正立へ戻せたfloating画像をページ上端から配置する。PNGのsampleや描画順は変更しない。

## 原本で確認する範囲

所属ページの検証済み回転角が90・180・270度であり、元CTMの成分が正確な直角の相殺を表す場合に限る。90度では`a=d=0, b>0, c<0`、180度では`b=c=0, a<0, d<0`、270度では`a=d=0, b<0, c>0`を要求する。全成分は有限である。丸めて得た角度だけから、元の行列の向きを決めない。

画像全体が検証済みMediaBoxとCropBoxの表示領域内にあることを確認する。反射、微小な傾き、ページ外、部分切り抜き、未検証ページは対象外にする。Formのclipを持つ画像にも広げない。追加配列や画素bufferは確保しない。

既存のviewport処理が回転させる`bounds`と整合するよう、90・270度の場合は`width_px`と`height_px`を入れ替え、確認済みの相殺では`rotation_degrees=0`にする。`ParsedPage`の元のページ寸法と回転角は維持する。公開structのfield追加、CLI・設定・依存の変更はない。

## Wordの上端原点

相殺済みの画像は、正の有限な表示矩形と表示pxの整合を検査し、PDF pointからEMUへ物理寸法を変換する。ページ内に全体があり、位置がWordの符号付きEMU範囲に収まる場合だけ、表示ページの上端からの距離`display_height - bounds.y1`を使う。90・270度の`display_height`は元ページの幅である。

画像に回転が残る場合や、寸法・ページ角度・表示領域を確認できない場合は、既存の配置を保持する。横並び画像の選択範囲や本文・表の所有を、この修正によって広げない。ページ内の座標が正しくても、本文flowによる余分なWordページの発生を解消したことにはならない。

## 所有する回帰

正式xrefを持つ非正方形の合成PDFと、水平な赤・緑の二画素を使う。90・180・270度について独立に求めた四隅、相殺後の表示寸法、角度0と全sampleを検査する。位置・寸法を変える48例のPBT、および反射・傾き・ページ外・CropBoxの否定例を含む。

Word生成では、異なるページ寸法を持つ90・270度のページ上端を検査し、直角3種と小数座標を変える32例のPBTを使う。未確認の角度・寸法・領域へページ原点の配置を拡大しないことも確認する。parserの回転が残る失敗と、Wordの余白原点の失敗を、それぞれ先に保存した。

## 固定原本での試作

[労働力調査の原本57条件](source_white_fill_and_adjacent_tables.md)を、既知資料への追試に使う。原本・初回結果・goldは変更しない。8画像の元CTMは、すべてページ90度と厳密に相殺される形だった。

native試作では、原本のロゴが実際のWord2ページ目の上部右側へ戻った。元PNGはバイト一致し、出力PDF内の画像寸法は元の293×133pxを保持する。原本のCTMから求めた位置・物理寸法とのレンダラーの差は最大0.031ptで、ページ内に全体が表示されることを目視した。ロゴの元の外観条件を満たす試作として記録し、全runtimeの最終判定は別に行う。

変化したWord2〜4ページをすべて目視し、1ページ目は目視済み親とRGB一致した。画像drawingだけを除くと本文XMLは親と一致し、画像を含むその他のZIP部品もバイト一致した。非空白1,164文字・4表・4ページは維持する。

大型CCITT stencil2点は、独立decoderでも元から全画素が透明だった。表示中のグラフの線はベクター描画であり、mask画像の位置を直してもその線は戻らない。グラフを誤認した9×96の表、原本2→Word4ページ、本文のはみ出し、font・clipping・全体の外観は依然として未達である。`whole_document_accepted=false`と`production_ready=false`を維持する。
