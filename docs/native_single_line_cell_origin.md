# 原本の一行セルの水平位置

原本で一行に収まる番号も、DOCXの既定の左右セル余白で表示幅が減り、二行へ
折り返すことがあった。一行のrun styleと字面が旧モデルへ完全に対応し、原本の
行の左右端がセル内に収まる場合は、原本左端からセル左端までの相対量を段落の
indentへ設定する。セルの左右余白はゼロにし、中央・右揃えを重ねない。

既存の段落をそのまま使い、段落ID、run、font、字面、行box、従来の縦中央配置を
保持する。styleが不明、原点が左罫線より外、または右端が右罫線を越える場合は
従来の水平配置へ戻す。複数行セル、OCR表、子表にはこの補正を追加しない。
公開API・既定制限・依存は変更していない。

所有する26pt幅・16pt文字の二桁セルでは、変更前の描画が縦に「1」「0」となり、
変更後は同じ16ptの一行になった。32例のproperty testで表の移動、列幅、文字サイズと
相対原点を変え、原点・字面・sizeの保存を確認する。左端・右端を越える行やstyle不明の
対照も持つ。原本座標からのindent保存と、置換fontを含む描画全体の完全一致は別である。

事前登録済みの国税庁の日本語表では、番号10〜20と見出し「番号」の折り返しが
解消された。二つの表と30セルの論理対応を保持する。大きい複数行セルが書式のない
本文へfallbackして文字が切れる問題、見出し画像のdecode、曲線、footerの再現は残る。
資料全体の合格やproduction readyは主張しない。

右端の条件がない中間版では、BERTの推定gridを越える「BERT」へindentを加え、
新たな折り返しを起こした。描画比較で検出して不採用とし、所有する右端越えの
回帰テストを先に追加した。現在はその二セルの従来配置を保持する。

検証では本文XMLの変更を一行セルの相対indent・既定配置の解除・左右余白へ限定し、
他のXML、font、画像、headerをbyte単位で照合する。全入力の表推定・font置換・
ページ数の正確さを保証するものではない。

既定構成のClippyとテストは2,395件成功・失敗0件・32件ignore。nativeの18結果、
Chromium・WebKitの計68結果を照合した。59ページの候補描画のうち28ページを最終版で
再描画し、31ページはDOCXが直前の版と同一のため描画を再利用した。変化した13ページは
個別に目視確認した。[検証記録](../corpus/validation-native-single-line-cell-origin.json)を参照。

日本語資料の出典と事前goldは[登録](../corpus/manifest-japanese-table-holdout.json)を参照。
これは国税庁「印紙税額の一覧表」（令和8年6月現在）を選択・加工した検証結果である。
