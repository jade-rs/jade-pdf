# 原本の罫線中心から行間を保つ

PDFのvector罫線の中心間隔に、rasterの境界用の薄罫線補正を重ねると、原本60ptの行が60.5ptになる。原本軸が一意で、全非空セルの本文・font・内側の行容量を確認できる2行以上・2列以上の非結合gridだけ、中心間隔をそのままWordの行高へ渡す。

上下罫線の半幅ずつを文字の容量から予約する。結合セル、曖昧な原本軸、未確認のfont・本文・容量は従来の高さを使う。子表の割当後に親の容量を改めて確認できないため、入れ子の親は精密化前の高さへ戻す。文字行の論理分割より前に戻し、物理行と分割後の行indexを混同しない。

単一の質問枠や一方向の帯は対象外とする。検証途中の候補ではNTAの質問枠を約1pt縮めたが、Wordの折返しを含めた実容量を証明できず、最後の質問の文字が下辺に重なる既存の不具合も残った。この候補は採用保留とし、元の失敗、全体テスト、772変換、全19追加ページの目視を保存した。対象を二次元gridへ限定する条件も、実際の失敗テストから追加している。原本のgoldや最初のNTA6/62を変更しない。

行高、罫線内側の容量、入れ子の親と子、単一枠・一方向の帯、曖昧な境界、未確認font・セル、結合、32例の座標移動・拡大・線幅を含む10テストが成功する。公開API・CLI・依存・tracked PDF/font fixtureは追加しない。[kanpo-parser / kanpo-docxの参照記録](source_typography_and_table_opening.md#参照)にある、原本gridとセルの所有を先に確認する考え方に沿う独立実装である。

既存の所有4ページPDF二種類では、原本の60pt・60pt・全高120ptを0.05pt以内で保持し、96文字と2列2行の構造も残る。ただし基線の誤差は+1.906〜+2.506ptで、原本の0.05pt条件を満たさない。下段の誤差は旧候補から0.5pt増える。罫線間隔の改善を文書全体の表示合格へ読み替えない。段落末尾や段落styleのfont継承を変える所有資料の診断でも、全ページのPNGと基線が変わらず、この仮説は否定された。

二次元gridへ限定した候補は全体テスト・native/WASM追試の再検証中である。既知資料の追試をインターネットの新規・未見資料の精度として数えない。Microsoft Wordの表示、基線、NTA本表、官報・CPI・労働力調査に残る問題は未解決で、文書全体のproduction readinessは未達である。
