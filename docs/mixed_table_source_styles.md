# 混在ページの推定表と原本書式

罫線表を持つ文書の別ページにある反復列を新しくWord表へ取り込む際、セル文字列を構成した原本断片をそのまま保持する。各セルについて、区切り空白と順序を含めた原文の完全一致を確認してから、font family・サイズ・色・太字・下線をrunへ渡す。曖昧な対応へ書式を割り当てない。本文の段組や表内に表現できない注記を除外する既存のガードも維持する。

列は繰り返される左端間の距離、行は元の行上端間の距離を使う。最後の列と行は元の文字範囲まで確保する。罫線のないセルに罫線を追加せず、セル上揃えと左右余白0を使う。同寸のページでも、この新しい推定表を含む文書ではページごとのsectionに原点を保存し、先頭ページの余白を別ページへ流用しない。

この書式・配置の変更は、混在文書で新しく開いた罫線なしページの推定経路に限定する。既存の全ページ罫線なし表や、罫線表を文字反復列に置き換える経路へ一括適用しない。これらには白文字と背景の対応など、別途検証が必要な課題が残る。

## 標準太字の文字幅

`/Widths`のないType1の`Helvetica-Bold`と`Helvetica-BoldOblique`には、確認済みの印字可能ASCIIのglyph advanceを使用する。通常体の幅やUnicode概算幅へ戻すことで末列が短くなり、太字が折り返して切れる問題を防ぐ。明示された`/Widths`を優先し、`/Differences`を持つ再符号化font・subset名・未知の符号化・対応範囲外のcodeへ標準幅を流用しない。

幅の数値は既存と同じ固定ReportLab4.4.9の一次配布物から生成する。実装やfont programは取り込まず、runtime依存も追加しない。[出典とハッシュ](../crates/jade-pdf2docx-parser/resources/standard-bold-widths.json)と既存の[ReportLabの利用条件](../crates/jade-pdf2docx-parser/licenses/reportlab.txt)を保持する。95件の数値はAdobe AFMとも照合した。再生成確認は`python3 tools/generate_standard_bold_widths.py --check`。

## 検証の範囲

所有する検証用PDFの原本を全ページ確認し、変換前に文字・書式の期待値を固定した。元の6件の原本は生成処理の拡張後もbyte単位で一致する。公開byte変換の回帰・プロパティテストに加え、CLIでの変換とLibreOffice描画を照合する。文字がXMLに存在しても、実描画で切れる場合は成功扱いにしない。

原本HelveticaからArialへの置換によるbaseline差、罫線表の文字位置などは残る。所有対照は既知の入力であり、未見文書の精度率を示さない。全体のruntime検証と変更出力の確認が終わるまで本番品質の合格とは扱わない。

依頼されたkanpoの設計から参考にした、文字と物理gridの所有対応・通常体と太字の区別・元の辺の根拠を保つ考え方は[参照記録](source_typography_and_table_opening.md#参照)に記載した。独自ライセンスのコードは転記せず、既存のIRとbuilderへ独立に実装している。
