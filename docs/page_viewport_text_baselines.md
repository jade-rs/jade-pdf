# 表示原点と基線をそろえ、回転本文の数字を保持する

bytes/WASMの抽出では、CropBoxやMediaBoxの有効原点を文字矩形へ反映した後も、`baseline_y`が元の描画座標に残っていた。原点Y=50、文字原点Y=80なら、矩形はY=30なのに基線だけY=80となる。また、ページを回転した後も元の正立文字の基線が残り、Wordで不適切な行結合や文字上げを起こした。

## 座標と確信の範囲

pure Rustのbytes/WASM抽出で、確認済み基線から有効表示原点Yを矩形と同じように一度だけ差し引く。Form・CTM・文字上げを合成した基線へ適用する。正立を確認できる回転ゼロの値だけを残し、非ゼロのページ回転後は`None`へ戻す。未知の基線を推測で補わず、非有限値と計算overflowも`None`にする。一部だけ表示される字面の基線は枠端へ丸めず、相対座標が負ならそのまま保持する。native SDK自体の抽出座標を書き換える変更は加えていない。native Word変換も、既存の照合経路で採用するpure側の幾何と基線を利用する。

この修正を調べる対照で、270度回転した本文の上付き数字がWordから消える別の問題を見つけた。回転したA・2・Bの数字だけが下端12%へ来ると、数字だけの行をページ番号として除去する従来の判定に入っていた。修正前の通常・strictの両方で発生し、基線だけを修正した試作でも欠落した。

90度・270度の一意なページで、表示行に正確に対応する元の数字の字面を照合する。正立基線が未知で、同じfontの近接する非数字の本文字形が同じ回転列の上下にあるとき、その数字を本文へ残す。有限で正の字面・文字サイズ、列の重なり、前後両方の接続を確認する。片側だけ、別font、離れた列、既知の正立基線、曖昧なページではこの本文判定を加えない。既存のページ番号・footer経路との対照も維持した。公開field・CLI・依存の追加はない。

## 固定した検証

親は`83265027150f5f8b89351181d336f6cc99ca94d7`、最終実装は`11743ef35e3f2f6243ddb8860c5270aefff4a5a9`。Rust1.93.1のCI defaultは2,705成功・0失敗・42無効化、165テスト群で、802個のRust sourceが実行前後で一致する。fmt、fixture hygiene2件、WASM distribution10件も通過した。公開回帰はparser7件・Word4件、private回帰は3件。32例の切り抜き・平行移動PBTと24例の本文・回転PBTを含む。2回の実際のRedは、実行した全Rust sourceを固定コミットからbyte一致で再構成できる。

基線だけを修正した最初の全体実行は2,699成功だったが、追加した所有原本の数字欠落を合格にしなかった。欠落した12結果、元のgold、試作出力を保持し、公開API回帰が失敗することを確認してから本文の数字を修正した。平行移動PBTの最初のbyte比較は、f32の字面端46.8と46.800003を同一と要求して失敗した。元の試験・seedを残し、字面の算術丸めだけ0.0001ptまで許容する。基線と他属性は厳密に照合し、実際の変換payloadは正規化しない。

既存native210件とChromium/WebKit各218件、計646結果の成否とpayloadはすべて親へbyte一致し、各109inspectionも一致した。追加は4回転それぞれの切り抜き前後の所有PDF8件、各runtimeの通常・strict計48結果で、成否とA・2・Bの3文字を一度ずつ保持する条件がすべて一致した。修正前に数字を落とした12結果で2が復元された。これらは既知の所有回帰であり、未知PDFの正解率へ数えない。

最終poolはnative226結果（197成功・29拒否）、Chromium/WebKit各234結果/117入力（200成功・34拒否）、計694結果。両ブラウザの234payloadと117inspectionは一致する。追加分の各16payloadはnativeにもbyte一致し、通常と成功したstrictも一致する。既存known11と追加した所有8件ずつの実行順序を固定している。

追加原本は、切り抜き前後の4組が独立したPDF描画でRGB一致することを、最初の変換前に確認した。新旧48通常出力は7種類のbyte列へまとまり、7ページすべてを独立描画して個別に目視した。270度はABからB・2・Aの各文字へ戻る。90度は上に2、下にABという試作からA・2・Bの行順へ変わる。180度は誤った正立基線による文字上げを解除する。正立0度は親とbyte一致し、原本の6pt文字上げはWordの12half-point位置を維持する。切り抜き前後の一致は親でも成立していた条件で、新たな外観の合格として加算しない。

回転した字形は依然として正立の横書きfallbackで描かれ、原本の文字方向・font metrics・絶対位置の完全な再現は未達。今回の上下の本文字形を確認できない孤立数字は従来のfooter判定を使う。strictの成否一致も、回転した原本全体の外観を認定するものではない。

81個の原本・gold・初回・保留結果manifest、延べ65,801ファイルを再照合した。既存payloadのbyte一致で、労働力調査36/57（21未達）、CPI26/107（81未達）と各runtimeの描画を継承する。公的資料の新しい原本条件の合格は増えていない。グラフ・clipping・font・改ページと全体の外観は引き続き未達。
