# テキストの段組みと表・画像ページ

構造化変換は、検出できた2段本文をページ単位のWord sectionへ変換する。
別のページに画像や推定表があっても、それらを含まないページの実段組は維持する。
ページ最後のblockが画像の場合は、その画像段落にsection境界を付ける。
表が最後の場合は、表の外に最小行高の境界段落を置く。
推定表とともに渡す互換用の表要約も、他ページの段組みを無効にしない。
floating画像だけ・反復見出しだけのページにも、確認できる原本寸法とsection境界を保つ。
画像の所有バイト列は従来どおり移動し、本文へ埋め込む。

段の原点は、実際に出力する整数twipのページ幅・左余白と段間隔から計算する。
原本の段間隔がWordの均等段間隔と異なる場合は、符号つき段落indentで原本の左端へ合わせる。
負のindentを0へ切り上げない。端数座標は、出力sectionと同じ単位へ変換してから扱う。
未確認・ページ外・表現不能の位置から新しいindentを作らない。

所有する自作PDFでは、2ページ目の画像が1ページ目の段組みを無効化する問題と、
段組みを復元した際に右段が10.75ptずれる問題を再現した。
修正後のnative DOCXをLibreOfficeで再描画し、選択した右段ラベルの横誤差は0.10ptだった。
画像を1ページ目へ移した入力でも、画像が元のページに残り、2ページ目の実段組が維持された。
これは選択した所有入力の検証であり、任意の文書やMicrosoft Wordの再現保証ではない。

追加の自作PDFは「表だけ・二段本文・表だけ」の3ページで、変換前に全ページと正解座標を固定した。
nativeとpureのLibreOffice出力はいずれも3ページで、24個の本文ラベルの最大横誤差は0.10pt、
最大baseline誤差は修正前nativeの222.8ptから2.2ptへ減った。表2個とセル8個の内容も維持した。
一方、表の文字は従来の縦中央配置のままで原本と異なる。ページ下端まで続く表の別入力は、
基準版と修正版の両方で3ページが5ページになった。表全体の再現精度は合格としていない。

実段組み候補の本文に次の段まで横断する未分割行がある場合は、その候補を適用しない。
推定表の制限を外すだけの試作版ではEfficientNetが27ページ、BERTが87ページへ悪化したため棄却した。
横断行の判定後は、既存6入力のnative/pure出力とBatch Normalizationのpure出力が基準版と完全一致した。

## 現在の制限

- 段組みの検出には、水平ギャップで分離できる複数行が必要。狭い段間隔を持つ論文などは未検証・未対応のまま残る。
- 画像または推定表を含むページ自体には、既存の配置を用いる。画像を含むページの2段本文も完全には復元しない。
- 位置のない明示OCR表、ページ・領域OCRを含む文書の複数ページ段組みは、この経路の対象外。
- 全ページが表だけ、見出しだけ、または完全な空ページである文書の一般的な再現は保証しない。
- フォント置換による字幅・最初のbaselineの差、図形、入れ子のForm、複雑な表や改ページの欠落は別途検証が必要。
- strictのOCR・文字対応などの診断は維持する。画像のページ所属が正しくても、未確認画像のstrict出力は拒否する。

公開PDF3件は以前のDOCXと同一だった。開発用に収集済みのBERT論文は以前と同じ出力で、
原本16ページが32ページになる問題や、表・Form・文字対応の欠落は解消していない。
全体のproduction-ready判定は行っていない。

[表ページの段組み検証](../corpus/validation-page-table-columns.json)を参照する。
