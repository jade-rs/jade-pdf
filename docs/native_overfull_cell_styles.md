# 表セルの配置が収まらない場合の文字書式

原本の表示行を段落として積み重ねるとセル高を超える場合は、既存の一段落の配置へ戻す。
この場合も、元のセル本文と空白を含めて完全に照合できる文字断片は、文字サイズ、書体、
太字・通常体、色を保持する。行boxは照合した文字の最大em高とし、最大em自体がセル高を
超える場合や不正なサイズがある場合は適用しない。

添字は、原本の同じ表示行で確認できた通常文字との基線差を保持する。
基線が不明な文字や、通常文字の基準が曖昧な場合に上下位置を推測しない。
同じ字形・書体・サイズでも別の文字断片へ他の断片の位置を使い回さない。

書式復元で新たに付ける下線は、原本gridの高さと両端に一致する水平罫線を除いて確認する。
gridの整数座標への丸め幅内で一致する境界が対象で、セル内の短い独立した本文下線は保持する。
既存本文の断片間へ補う空白には下線を延長せず、原本で下線を持つ文字と別のrunにする。
閉じた枠だけで構成される表では、従来どおり枠を文字下線として扱わない。

本文の文字列、段落数、セルの高さ・結合・配置は保持する。元の複数行や縦位置を再現する
機能ではない。新しい段落を余分に生成しないため、無関係なheader/footerの段落IDも変えない。
公開API・CLI・依存の追加はない。

## 検証と残る問題

所有PDFのテストでは、10ptと14ptの文字、太字と通常体、赤と青、同じ5pt文字の
上付き・下付き、表罫線と独立した本文下線を区別して確認する。
元の本文との完全一致や既存のfallback条件も維持する。

国税庁の印紙税額一覧では、原本約8ptの書式を保持すると、既定サイズへ戻していた大きなセルの
契約種類2〜4が表示される。元の23行を復元した結果ではなく、既存の一段落で再flowした結果である。
本文349文字の変更前との一致は確認するが、新たな独立した全文正解データとは数えない。
原本の暗号化、画像、曲線、strict拒否、ページ全体の表示問題は別の課題である。

同文書の別ページでは、本文XMLを変更しなくてもLibreOfficeの描画位置が最大0.022pt変わった。
書体と8ptサイズを個別に切り分けた対照実験で、両者の組合せによる描画contextの変化を確認した。
内部のfont処理の機序やMicrosoft Wordでの表示は未確認で、画素の完全一致とは判定しない。

Batch Normalization論文のブラウザ変換では、原本の表内文字に必要な埋め込みfaceが一つ増える。
既存faceの復号後データは同一で、新規faceも原本解析時のデータと一致することを確認する。
fontファイルの番号・難読化keyの移動は、この対応を調べて検証する。
文字書式の保存は数式全体の正しさを意味せず、既存の不明文字、行の再flow、ページ数の差は残る。
原本PDF・font・生成DOCXをリポジトリへ追加せず、既存の権利確認済みprivate QA入力を使う。

この修正の限定した検証範囲は、[検証記録](../corpus/validation-overfull-cell-styles.json)を参照。
表と書式を原本の情報へ対応づける方針は、調査済みの
[kanpo-parser / kanpo-docxの設計](source_typography_and_table_opening.md#参照)も参考にしている。
